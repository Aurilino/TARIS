# Зашифрованный манифест и чтение объекта

> [[01_plan|Общий план]] · [[30_step3_simulation_spec|Спецификация среды]] · [[55_step5_agent_plan|Агент TARIS]]

## Решение автора от 03.11.2026

Принят вариант с зашифрованным манифестом. Ключ пользователя открывает описание сборки объекта; агент организует получение фрагментов, а клиент пользователя восстанавливает и расшифровывает данные. Первоначально это проектируемое расширение. На 03.11.2026 реализован и проверен отдельный локальный прототип ([[60_crypto_demo_results]]); связь с журналом текущего симулятора добавлена отдельным слоем анализа и байтовой сверки ([[61_security_integration]]); политика и прежние метрики пока не изменены.

Секретность не опирается только на скрытый порядок чанков. Перед кодированием объект шифруется готовым алгоритмом аутентифицированного шифрования. Даже собрав достаточное число фрагментов, сторона без ключа получает только зашифрованный объект.

## Содержимое манифеста

- Идентификатор объекта и версия манифеста.
- Идентификаторы фрагментов, их индексы для декодирования и проверочные значения целостности.
- Алгоритм кодирования, число необходимых фрагментов и общее число фрагментов.
- Алгоритм шифрования объекта, nonce и необходимые параметры проверки подлинности.
- Длина исходного объекта и сведения, необходимые для устранения дополнения при декодировании.
- Ссылки на поиск текущих держателей фрагментов. Идентификатор фрагмента сохраняется при переносе; физическое местоположение может изменяться.
- Ключ объекта, защищённый шифрованием манифеста, либо ссылка на отдельную защищённую оболочку этого ключа. В открытые метаданные ключ объекта не попадает.

Сам манифест также защищается аутентифицированным шифрованием. Ключ манифеста и ключ объекта различаются. Их генерация, хранение и выдача относятся к клиентскому криптографическому слою и требуют отдельной спецификации до реализации. Самодельные алгоритмы шифрования не разрабатываются.

## Запись объекта

1. Клиент создаёт ключ объекта и шифрует содержимое с проверкой подлинности.
2. Система кодирует зашифрованный объект в избыточные фрагменты.
3. Агент выбирает держателей с учётом риска, связанных владельцев и ограничений размещения.
4. Клиент формирует и шифрует манифест. Пользователь получает устойчивый идентификатор манифеста и сохраняет средство доступа к ключу.
5. Манифест хранится с резервированием. Его потеря учитывается отдельно: наличие фрагментов без инструкции декодирования не означает доступность объекта для пользователя.

## Чтение объекта

1. Клиент по известному идентификатору получает манифест и расшифровывает его ключом пользователя.
2. Клиент проверяет подлинность манифеста и ожидаемую версию. Защита от подмены старой корректной версией требует доверенного указателя актуальной версии.
3. Агент получает минимально необходимые сведения для загрузки: идентификаторы фрагментов и параметры запроса. Ключи и открытое содержимое манифеста целиком ему не передаются.
4. Агент организует загрузку достаточного числа разных фрагментов. Клиент проверяет их целостность и выполняет декодирование.
5. Клиент расшифровывает восстановленный зашифрованный объект и проверяет его подлинность. При провале проверки данные не выдаются как корректные.

При избыточном кодировании индексы обозначают строки кодирования, а не только порядок склейки: достаточное допустимое подмножество фрагментов восстанавливает объект по параметрам кода.

## Границы защиты

Агент управляет риском размещения и доступностью. Криптографический слой защищает содержание и подлинность. Агент и узлы хранения не получают ключи расшифрования. Для восстановления утраченных фрагментов используются зашифрованные данные; открытый текст не требуется.

Манифест скрывает описание сборки, но запросы агента могут раскрывать связи между загружаемыми фрагментами. Сокрытие сетевого трафика и шаблонов доступа в это решение не входит.

Компрометация клиентского ключа, потеря ключа, отзыв доступа, обновление манифеста и защита от отката версии описаны в [[57_threat_model_keys|модели угроз и жизненном цикле ключей]]. Базовый вариант — один владелец; обмен с несколькими пользователями отложен. Смена ключа доступа не заставляет противника забыть уже полученный ключ объекта или открытый текст.

## Совместимость с существующей моделью

Текущий симулятор использует пороговое допущение AONT-RS: коалиция, накопившая достаточное число различных фрагментов, считается раскрывшей объект. Этот режим сохраняется как прежний экспериментальный базис; существующие результаты не переименовываются и не пересчитываются автоматически.

Для нового режима следует раздельно учитывать:

- накопление коалицией достаточного числа фрагментов зашифрованного объекта;
- компрометацию ключа объекта или возможности его получить;
- раскрытие открытого содержимого;
- недоступность манифеста и потерю клиентского ключа;
- отказ проверки целостности фрагментов, манифеста или объекта.

Сбор достаточного числа фрагментов сам по себе не считается раскрытием открытого текста в новом режиме. Вероятность компрометации ключей нельзя выводить из статистики отказов узлов хранения.
