# I4.5a. Оценивать запас информации, а не число записей

Дата: 11 ноября 2026 года.

Добавлен внешний пересчёт по физическим журналам `object_reserve.py`. Он измеряет запас разных номеров чанков на всём сроке наблюдения. Целая отключённая копия учитывается; две копии одного номера дают один номер кода, но обе требуют хранения. Показатели используют истину после прогона и не передаются агенту.

## Время недовосполненного запаса

$$
E_o^{\mathrm{below}}(n) = \int_{c_o}^{T} \mathbf{1}\!\left(|S_o(t)| < n\right)\,dt.
$$

где:
- E_o^{below}(n) — время объекта ниже запрошенного числа разных номеров, в сутках;
- o — объект;
- n — запрошенное число номеров, в рассматриваемых сериях 4;
- c_o — момент создания объекта;
- T — конец выполненного горизонта;
- t — время;
- S_o(t) — множество разных целых дисковых номеров объекта;
- вертикальные черты — мощность множества;
- 1(условие) — индикатор истинности условия.

$$
A_o^{\mathrm{short}}(n) = \int_{c_o}^{T} \max\!\left(0, n - |S_o(t)|\right)\,dt.
$$

где:
- A_o^{short}(n) — недовосполнение в номеро-сутках;
- o — объект;
- n — запрошенное число разных номеров;
- c_o — момент создания;
- T — конец горизонта;
- t — время;
- S_o(t) — множество целых дисковых номеров;
- вертикальные черты — мощность множества;
- max — операция ограничения снизу нулём.

Эти величины различаются: двое суток с тремя номерами при цели четыре дают две номеро-сутки, а двое суток с двумя — четыре номеро-сутки. Время ровно с k номерами выделяется отдельно: код ещё восстановим, но избыточности по разным номерам уже нет. Дисковый дефицит ниже k и защита полным буфером остаются отдельными показателями.

## Дубликаты и стоимость хранения

$$
D_o^{\mathrm{copies}} = \int_{c_o}^{T} \left(F_o(t) - |S_o(t)|\right)\,dt.
$$

где:
- D_o^{copies} — расход полных копий сверх числа разных номеров, в копие-сутках;
- o — объект;
- c_o — момент создания;
- T — конец горизонта;
- t — время;
- F_o(t) — число целых полных физических копий;
- S_o(t) — множество разных целых номеров;
- вертикальные черты — мощность множества.

Дубликаты не обязательно бесполезны: два носителя одного номера могут пережить гибель одного из них. Но они не заменяют другой отсутствующий номер и не увеличивают ранг кода. Поэтому этот показатель нельзя минимизировать как единственный критерий надёжности.

Копие-сутки сверяются с прежним аудитом физической жизни копий. Объёмо-сутки дополнительно учитывают размер чанка. Память, временная область получателя и трафик имеют другие единицы; цены для них нельзя молча подменять стоимостью хранения одного фрагмента из прежнего уравнения Тиле.

## Результат и границы

Пересчитаны 72 исполнения и 3240 объект-размещений из уже существующих журналов. Это не новые миры и не 3240 независимых испытаний. Показатели экспозиции, копие-суток, дискового дефицита и защиты буфером совпали с прежними аудитами.

Обнаружен пример, который не виден по нулевому счётчику потерь: в новой проверочной серии медленного Classic код находился ровно на пороге k=2 суммарно 2,206 объекто-суток. Потери не было, но запас разных номеров отсутствовал. Это не оценка вероятности потери — только измеренная экспозиция.
