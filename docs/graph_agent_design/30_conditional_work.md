# Условная оставшаяся передача — I4.7a

Расчёт получает только наблюдаемый снимок второй версии. В момент снимка текущая передача условно прерывается. Неподтверждённый блок повторяется целиком; остаток старой фазы отдельно не прибавляется. После снимка предполагаются немедленная доступность, отсутствие повторов, отмен и новых заявок.

Объём для незавершённого задания:

$$
V_j(t) = B_j - M_j(t) + \sum_{i \in I_j(t)} \frac{B_j}{k} \cdot \left(1 - \frac{a_{ji}(t)}{s}\right) + p \cdot B_j.
$$

где:

- V_j(t) — условный объём передачи задания j на границе t;
- j — номер незавершённого задания восстановления;
- t — время снимка в сутках;
- B_j — размер объекта задания j;
- M_j(t) — подтверждённый объём объекта в собственной памяти задания, от нуля до B_j;
- I_j(t) — текущие заказанные номера фрагментов задания;
- i — номер фрагмента;
- k — число различных фрагментов для восстановления объекта;
- a_{ji}(t) — число блоков, зачтённых выбранным условным сценарием для получателя этого номера;
- s — число блоков в одном фрагменте;
- p — доля размера объекта для одной успешной закрывающей проверки.

В `trust_ack` зачёт равен последнему успешному подтверждённому префиксу. В `restart_partial` незавершённому фрагменту зачёт равен нулю; полностью подтверждённый фрагмент сохраняет зачёт s. Оба сценария предполагают сохранность полностью записанного фрагмента после последнего ACK. Это допущение нельзя проверить по одному старому ACK.

Последний меньший префикс после перезапуска заменяет старый больший; максимум по всей истории был бы ошибкой. Неуспешный блок сам по себе не аннулирует предыдущий успешный префикс. Расчёт не утверждает, что этот префикс действительно сохранился сейчас.

Условная цена передачи:

$$
C_{\mathrm{tr}}(t) = c_{\mathrm{tr}} \cdot \sum_{j \in J(t)} V_j(t).
$$

где:

- C_{\mathrm{tr}}(t) — условная цена передачи по текущим заданиям восстановления;
- c_{\mathrm{tr}} — заданная цена единицы переданного объёма;
- t — время снимка;
- J(t) — множество текущих незавершённых заданий восстановления;
- j — номер задания;
- V_j(t) — условный объём передачи задания.

Самостоятельные proof-задания пока имеют неизвестный объём: контракт не сообщает количество и размер проверяемых копий. При их наличии общая сумма очереди возвращается как неизвестная. Цена памяти во времени, ожидание, подготовка, будущие повторы и ущерб также неизвестны. Деление объёма на скорость даёт время непрерывной передачи, не срок завершения задания.

В контролируемом runtime-примере после отказа собственной памяти условная работа возрастает с 1,1975 до 1,51 единицы объёма. При частично записанном получателе сценарии дают 0,26 и 0,51. Это проверка реакции расчёта на наблюдаемое состояние, а не статистическая оценка частоты потерь.

Артефакты: `subprojects/taris_variants/conditional_work.py`, протокол `EXPERIMENT_I47A.md`, результаты `conditional_work_i47a/`. Новые случайные миры и изменения политик отсутствуют.

## Проверка продолжением I4.7b

`check_continuation.py` проверил три границы чтения/записи без новых отказов и одну ветвь с будущим прерыванием источника. Без отказа условный объём отличается от обычного продолжения ровно на уже обслуженную часть текущего блока: 0,0075; 0,00875; 0,03. В ветви прерывания дополнительный объём равен 0,0625. Наблюдаемые снимки перед будущим событием совпадают; все задания завершились.

Это доказывает согласованность учёта для данных контролируемых примеров, но не калибрует будущие повторы. Ожидающий самостоятельный proof остаётся неизвестным; плановый объём становится доступен после подготовки его фазы. Следующий этап — новые парные случайные прогоны с runtime-снимками и метками последующего обслуживания, включая незавершённые задания.
