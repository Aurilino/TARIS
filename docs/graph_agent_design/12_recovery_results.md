# Р4. Исполнение восстановления

Дата: 10 ноября 2026 года. Реализован автономный событийный исполнитель, без изменения основного Ledger.

## Устройство

`prototype/recovery.py` разделяет физические чанки и наблюдаемый каталог. Отключение не уничтожает данные. Тихая потеря меняет только физическое состояние; каталог обновляется после аудита или неуспешной проверки чтения. Политика получает неизменяемый `NetworkSnapshot`, без ссылок на среду, истинные чанки и будущие события.

Объект задаёт свой порог сборки и целевой запас. Разные чанки имеют индексы; несколько копий одного индекса не увеличивают число разных чанков. На одной ноде хранится не более одного чанка данного объекта.

Операция восстанавливает один чанк. Место получателя резервируется при принятии запроса. Повторный запрос на тот же индекс или получателя не создаёт конкурирующую копию. В первой фазе читаются необходимые разные чанки, во второй — записывается новый. Новый чанк считается существующим только после подтверждения записи.

При наличии уже собранного объекта в буфере повторное чтение источников не требуется. Буфер — явное хранилище информации у исполнителя. Он сохраняется, пока целевой запас не восстановлен и нет незавершённых операций. Для него есть отдельное событие потери. Отказ источников после завершения чтения не обязан прерывать запись, потому что данные уже в буфере.

## Ресурсы и время

Время этой автономной модели — часы, размер одного чанка — одна условная единица. Это отдельная шкала от основного симулятора, где время задаётся сутками. При подключении необходим явный перевод единиц.

Нода имеет ёмкость и пропускную способность; площадка может иметь общий канал. Одновременные потоки поровну делят каждый общий ресурс, скорость операции определяется самым узким ресурсом. Синхронное чтение нескольких источников ограничивается самым медленным из них. Это простая консервативная модель обслуживания, не оптимальный сетевой планировщик.

Есть лимит одновременно обслуживаемых операций. Недоступная операция ожидает и не занимает активный канал; другие готовые операции могут выполняться. Событийный шаг выбирается по следующему внешнему событию, завершению передачи или моменту решения. Времена и объёмы вычисляются рациональными дробями.

Если завершение совпало со временем внешнего события, сначала обрабатывается завершение, затем событие. Это явная договорённость дискретной модели; другие порядки могут менять пограничные случаи.

## Результаты

| Пример | Результат |
|---|---|
| Нода временно выключилась и вернулась | Восстановление завершено через 2 часа; старая копия сохранилась; четыре физические копии содержат три разных индекса |
| Тихая потеря в начале, аудит через час | До аудита операция не начинается; новая запись подтверждена в час 3 |
| Два восстановления, общий канал получателей 1 ед./час | Оба завершаются в час 4 |
| Те же операции, канал 2 ед./час | Оба завершаются в час 3 |
| Источник повредился во время чтения | Операция провалена, место освобождено; после возвращения другого источника повтор завершается в час 6 |
| Источники уничтожены после чтения | Явный буфер позволяет продолжить восстановление |
| В том же случае потерян и буфер | Объект признаётся потерянным в час 1,5 |

Для двух параллельных объектов в примере каналов суммарный трафик одинаков: шесть единиц чанка. Более раннее завершение обусловлено каналом, а не уменьшением объёма данных.

В примере буфера после восстановления может оставаться дефицит целевого запаса из-за нехватки подходящих живых нод. Буфер не удаляется автоматически при таком дефиците. Этот центральный резерв является дополнительным фактором сохранности и должен учитываться в будущей модели риска.

## Политика и ограничения

`RecoveryPolicy` выбирает источники только из наблюдаемого каталога и доступных нод; истинная проверка выполняется исполнителем при чтении. По умолчанию выбор ноды детерминированный; можно передать модель риска и использовать согласованный предварительный критерий собственного и парных рисков. Это не полноценная оптимизация динамического риска объекта на всём пути восстановления.

Буфер и каталоги не моделируют шифрование, ключи и протокол прав доступа. Буфер может представлять собранный зашифрованный объект; наличие данных у исполнителя не подразумевает наличие ключа расшифрования. Его объём пока не ограничен. Проверка записи идеальна, задержки пингов отсутствуют. Отмена лишних копий и экономическое высвобождение запаса в этой версии не реализованы.
