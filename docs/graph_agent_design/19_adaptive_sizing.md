# I3. Выбор числа чанков и проверка истинных параметров

Дата: 10 ноября 2026 года. Реализовано в отдельном подпроекте, основной TARIS не изменён.

Подробности: `subprojects/taris_variants/ANALYSIS_I3.md`, протокол `EXPERIMENT_I3.md`, результаты `series_i3/RESULTS.md`, независимая проверка `series_i3/AUDIT.md`.

Контроллер выбирает начальный размер в пределах 3–6 чанков при пороге сборки два. Во всех трёх стратегиях проверяются одинаковые требования потери за окно и доступности. Холодный старт и неудача поиска не объявляются выполненной защитой. Размер учитывается в восстановлении, а кэши расчётов резерва разделены по n.

На новых зёрнах 6–8, S2, 45 суток выполнены 27 исполнений: фиксированные три, фиксированные четыре, адаптивные 3–6, по три варианта. Все объекты приняты. Для каждой стратегии адаптивный профиль объявил успешными 107 проверенных размещений; ещё 28 — холодный старт.

Внешний аудит истинных интенсивностей той же модели окна выявил 19, 16 и 20 ошибочно безопасных размещений у Classic, G и Hybrid соответственно. При фиксированных четырёх чанках превышений оконного лимита по истинным параметрам не было в этих мирах. Это не число потерянных файлов и не гарантия на произвольной сети.

Адаптивное среднее число чанков — 4,30–4,36, расходы хранения выше фиксированных четырёх примерно на 17–19%. В адаптивных профилях и при фиксированных четырёх потерь по Ledger не было; Classic с фиксированными тремя потерял два принятых объекта.

Следствие: корректный подбор размера по точечной оценке не гарантирует корректность защиты. Следующий приоритет — консервативная оценка риска и проверка ложно безопасных решений на новых мирах, а не дальнейшее снятие запаса по текущей модели.

Прежние варианты и результаты I1/I2 сохранены. Адаптивный режим не включён по умолчанию. Проходят 30 проверок подпроекта и 56 проверок автономного прототипа.
