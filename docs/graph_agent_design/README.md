# Проектирование агента на полном графе рисков

Дата начала: 6 ноября 2026 года.

Статус на 10 ноября 2026 года: выполнен автономный прототип Р1–Р5 и Р6а (теневое чтение основной среды). Проходят 56 проверок. Р6б — исполнение в основном Ledger — не включён. Подробности и ограничения: `15_pipeline_status.md`.

Последующее расширение: по отдельному поручению автора создан `subprojects/taris_variants/` — три варианта исполняются в прежнем Ledger без изменения его семантики. Это первый интеграционный этап, не перенос нового физического учёта Р6б. См. `17_three_variants_integration.md`.

## Назначение

Рабочая папка для последовательного проектирования нового подхода TARIS: актуарно оценивать сохранность информации и выбирать размещение чанков через полный граф рисков совместного отказа нод.

Документы этой папки описывают проектируемый подход. Они не означают, что он уже реализован или заменяет действующую математическую модель. Источник истины для расчётов — Python-симулятор; просмотрщик воспроизводит журналы и принимает вмешательства через файлы сценариев.

Это отдельное направление внутри основного проекта, а не отдельная Git-ветка. Реализация находится в `prototype/`; основной код и действующие документы модели не изменяются. Наблюдения основной среды подключены только в режиме чтения.

## Порядок работы

1. Зафиксировать согласованную концепцию и открытые вопросы — выполнено в `01_concept.md`.
2. Определить смысл отказа, горизонт оценки и веса полного графа — согласовано, `02_graph_math.md`.
3. Описать постановку первичного размещения чанков одного объекта — согласовано, `03_placement_math.md`.
4. Определить параметры пересчёта графа для репликации и восстановления — согласовано, `04_recovery_math.md`.
5. Описать обучение оценок по наблюдениям и работу при недостатке данных — согласовано, `05_learning_math.md`.
6. Проверить постановку на небольших примерах: регулярные отключения, общая площадка, кризис, коллапс — `06_examples.md`, выводы приняты для продолжения.
7. Сопоставить проект с существующим кодом и составить план реализации и экспериментов — `07_implementation_plan.md`. Выполнены Р1–Р5 и Р6а; ограничения и оставшаяся работа — `15_pipeline_status.md`.

Первоначально шаги согласовывались по одному. С 10 ноября автор поручил продолжать автономно без промежуточных подтверждений. Этапы выполняются последовательно, результаты и ограничения сохраняются в файлах. Новое направление остаётся изолированным от основной модели.
