# Минимальный запас при доменных отказах — I7

Сначала решаем ограниченную задачу нового плана: каждый номер фрагмента различен, на одном узле не больше одного номера объекта, доменные метки достоверны, каждый назначенный узел может принять фрагмент. Это не сертификат текущей скрытой целостности и не модель реальной частоты катастроф.

Пусть числа номеров по доменам упорядочены по убыванию. Худший остаток:

$$
r_{\min}(x,b) = \sum_{d=1}^{D} x_d - \sum_{j=1}^{\min(b,D)} x_{(j)}.
$$

где:

- r_{\min}(x,b) — минимальное число разных номеров после отказа не более bдоменов;
- x — вектор распределения разных номеров;
- x_d — число номеров в доменеd;
- D — число доступных доменов с ненулевым числом допустимых узлов;
- d — индекс домена;
- b — фиксированный бюджет доменных отказов;
- x_{(j)} — j-е наибольшее число номеров среди доменов;
- j — позиция в порядке убывания; если bне меньшеD, выживающий остаток равен нулю.

Требование сохранности:

$$
r_{\min}(x,b) \geq k.
$$

где:

- r_{\min}(x,b) — худший остаток разных номеров при распределенииx;
- x — доменный план;
- b — число одновременно поражаемых доменов;
- k — число разных номеров для декодирования.

## Минимум без ограничений числа узлов внутри доменов

При Dбольшеb точный минимум:

$$
n^{*}_{0} = k + b\cdot\left\lceil\frac{k}{D-b}\right\rceil.
$$

где:

- n^{*}_{0} — минимальное общее число новых разных номеров без доменных ограничений ёмкости;
- k — порог декодирования;
- b — бюджет доменных отказов;
- D — число доступных доменов;
- потолок означает наименьшее целое, не меньше отношенияkкD−b.

Доказательство нижней границы: сумма номеров в D−bнаименее заполненных доменах должна быть не меньшеk. Самый заполненный из этих выживших доменов содержит не меньше указанного потолка. Каждый из bсамых заполненных содержит не меньше того же количества. Суммарно требуется не меньше правой части.

Достижимость: распределить kномеров в выживающей группе максимально равномерно, используя потолок и на единицу меньше; каждому из остальных bдоменов назначить потолок. После удаления любых bсамых заполненных остаётся kномеров. Так нижняя граница достигается. Если Dне большеb, все домены могут исчезнуть, дискового решения при положительномkнет.

## Ограниченное число допустимых узлов

Для реального списка кандидатов:

$$
n^{*} = \min_{x}\sum_{d=1}^{D} x_d,
\qquad 0\leq x_d\leq c_d,\quad x_d\in\mathbb{Z},\quad r_{\min}(x,b)\geq k.
$$

где:

- n^{*} — минимум разных номеров в ограниченной задаче;
- x — искомый вектор размещения;
- x_d — число назначенных номеров доменаd;
- D — число доменов;
- d — индекс домена;
- c_d — число различных допустимых узлов доменаd;
- \mathbb{Z} — целые числа;
- r_{\min}(x,b) — остаток после худших bдоменных отказов;
- b — бюджет отказов;
- k — порог декодирования.

Пустые домены не увеличивают D. Общий бюджет числа фрагментов может дополнительно ограничиваться max_n. Минимум без ёмкостей — только нижняя граница: например, при k=5,b=2иёмкостях[1,1,3,3,3]граница9, но точный минимум11. При k=2,b=3иёмкостях[2,2,2,1]решения нет: потеря трёх крупных доменов оставляет только один номер.

## Реализация и проверка

`domain_reserve.py` ищет общее число номеров по возрастанию и перебирает ограниченные целочисленные раскладки. Первое допустимое решение имеет доказанный минимум в этой задаче. Остановка по max_statesвозвращает неизвестную разрешимость, не ложный отказ и не сертифицированныйbest_effort. Порядок доменных меток может изменить выбранную раскладку, но не минимум.

Шесть тестов, включая независимый перебор подмножеств физических узлов на всех малых ёмкостях до трёх доменов, пройдены. Десять отдельных задач и их независимые минимумы сохранены в `subprojects/taris_variants/domain_reserve_i7/`. Примеры k=2: защита от двух доменов в четырёхДЦ—4номера; от трёх в пятиДЦ—5; от трёх в четырёхДЦ—8.

Решатель пока не подключён к политикам. Это минимум одного объекта при фиксированном снимке кандидатов, не глобальный минимум всей сети или даты с общей ёмкостью. Он не минимизирует стоимость среди равномощных раскладок, не оценивает скрытые потери, истинность DC-меток, частные устройства с dc=-1иуспешность будущей записи. Дубликаты существующих копий требуют отдельного учёта по разным номерам. Отказ безопасного размещения должен учитываться как отказ приёма, а не выдаваться за нулевые потери. Следующий шаг — адаптер наблюдаемого реестра и выбор конкретных узлов, затем отдельная экспериментальная политика.
