# Р6а. Наблюдения основной среды в режиме чтения

Дата: 10 ноября 2026 года. Выполнен адаптер наблюдений; замена политики и учёта основного симулятора не выполнялась.

## Граница подключения

`shadow_adapter.py` принимает простой неизменяемый срез: границы завершённого часового интервала, зарегистрированные ноды и ноды с текущим наблюдаемым простоем. Нет ссылок на World, Chain или Ledger. Пограничная функция читает только `Chain.observe` и публичные времена регистрации выбранных нод.

Используется согласованная семантика `Chain.observe`: список текущих простоев описывает наблюдаемое состояние у правой границы завершённого интервала. Отсутствие ноды в этом списке трактуется как наблюдаемая доступность только для зарегистрированных нод и при полном нормализованном срезе этого интерфейса. Это не правило для произвольного неполного журнала пингов.

Основной симулятор измеряет время сутками; адаптер переводит его в целые часы. Обучение получает по одному состоянию в час, а не точную долю простоя за час. День — часы 08–20, ночь — остальные. Число состояний ограничивает адаптируемую группу шестью выбранными начальными нодами, не всей сетью.

## Почему слой потери не обучен

В `Chain.observe` аудит `passed_avail` относится к наблюдаемой доступности; его провал не является подтверждением уничтожения конкретного чанка. Длительный простой тоже не считается такой меткой. Поэтому адаптер передаёт только доступность, а обучение физической потери не имитируется.

В теневых запросах ограничение физической потери отключено: допустимое значение установлено равным единице, а `loss_constraint_enabled` записано как `false`. Слой потери остаётся базовой моделью и может участвовать только в техническом разрешении равенств; он не имеет подтверждённого соответствия этому миру. Оценка будущей физической потери в отчёте — `null`.

Для полноценного подключения необходим отдельный наблюдаемый протокол целостности чанков, экспозиция их хранения, время получения подтверждения и разделение физической потери с административным признанием ненадёжности в Ledger.

## Малые прогоны

Сценарии S0, зерно 3; S2, зёрна 4 и 5. Каждый мир: 24 начальные ноды, 24 суток, для модели выбраны первые шесть уже зарегистрированных нод. Параметры приведены в `run_shadow_adapter.py`, хеш конфигурации — в отчёте.

- Обучение для выбора параметра: первые восемь суток.
- Историческая проверка: следующие восемь суток.
- Окончательная модель: по наблюдениям первых 16 суток.
- Будущий отрезок: последние восемь суток, 192 часовых состояния.
- Повторные выборки: четыре модели с блоками по 24 часа.

Часовые состояния в реальном генераторе зависимы. Блоковая схема лишь частично отражает эту зависимость; четыре повторные выборки не дают статистического доверительного уровня. Числа базовой модели Р3 не калибровались как часовые вероятности данного генератора; эти прогоны проверяют интерфейс и выявляют ограничения переноса.

| Мир | Чанков: точечная / bootstrap / комбинированная | Будущая наблюдаемая недоступность: точечная / bootstrap / комбинированная |
|---|---|---|
| S0, зерно 3 | 2 / 2 / 5 | 0 / 0 / 0 |
| S2, зерно 4 | 2 / 2 / 5 | 9,375% / 9,375% / 0 |
| S2, зерно 5 | 2 / 2 / 6 | 2,083% / 2,083% / 0 |

В S2 с зерном 4 наблюдаемая доля на будущем отрезке выше целевых 8%. Это реализация на 192 точках, а не знание истинной вероятности. Тем не менее она показывает, что нулевые нарушения bootstrap в учебных мирах не являются гарантией при переносе.

Комбинированная проверка оказалась существенно дороже по числу чанков и на этих отрезках не имела наблюдаемых перерывов. Отсутствие перерывов в трёх малых мирах не доказывает надёжность для всей сети и длинного горизонта.

## Неизменность основной среды

Для каждого прогона сравнивались хеши таблиц узлов, простоев, тихих потерь, наблюдений и аудитов до и после работы адаптера. Хеши совпали. Независимая повторная генерация с тем же Config дала те же таблицы. Хеши всех исходников `taris_sim/*.py` до и после запусков совпали.

Скрипт запускается с запретом записи байткода. Не меняет политики, настройки, журналы прошлых прогонов и исходники основного проекта. Пишет только `prototype/shadow_adapter_results.json`.

## Файлы и границы результата

`shadow_adapter.py`, `run_shadow_adapter.py`, `shadow_adapter_results.json`, `test_shadow_adapter.py`. В отчёте сохранены входные публичные срезы, решения, метрики и хеши.

Это Р6а — теневое чтение и оценка решений. Р6б — исполнение новой политики в основном Ledger с новой семантикой потерь, ресурсами и отдельным режимом — ещё не выполнен. Его нельзя незаметно включить вместо действующего режима: это изменит смысл прежних метрик.
