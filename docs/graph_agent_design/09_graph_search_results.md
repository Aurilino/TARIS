# Р2. Поиск через граф и сравнение с точным эталоном

Дата: 7 ноября 2026 года. Статус: Р2 реализован и проверен. Последующее обновление: базовая часть Р3 выполнена, см. `10_learning_results.md`.

## 1. Что реализовано

В автономный прототип добавлен `graph_search.py`: несколько детерминированных стартов, жадное расширение размещения и улучшение заменой одной ноды. Основной симулятор не изменялся. Входные вероятности по-прежнему заданы, обучение отсутствует.

Из `exact_model.py` выделены общая проверка области поиска и единый критерий сравнения допустимых размещений. Точный эталон и эвристика используют одинаковые ограничения, набор кандидатов и правила разрешения равенств.

## 2. Алгоритм

Сначала исключаются ноды без свободного места. Для оставшихся рассчитываются собственные риски и полный граф совместной недоступности. Стартовые ноды выбираются по возрастанию собственного риска недоступности, затем потери, затем идентификатора. По умолчанию берутся три старта или все ноды, если их меньше трёх.

Для каждого размера, начиная с нижней границы, каждый старт независимо расширяется до нужного числа чанков. Новая нода выбирается по минимальному приращению суммы рёбер:

$$
\Delta J(j\mid S)=\sum_{i\in S}w_{ij}(t,H).
$$

где:
- \(\Delta J(j\mid S)\) — увеличение графового критерия при добавлении ноды;
- \(j\) — нода-кандидат, не входящая в выбранный набор;
- \(S\) — уже выбранные ноды;
- \(i\) — нода выбранного набора;
- \(w_{ij}(t,H)\) — вес совместной недоступности на согласованном горизонте;
- \(t,H\) — момент решения и горизонт, заданные смыслом входного распределения.

Равенства разрешаются по собственному риску недоступности новой ноды, её риску потери и идентификатору. На этапе жадного расширения учитывается граф доступности; полный риск объекта проверяется после построения набора и при локальных заменах. Это не критерий динамического восстановления из шага 4.

После построения рассматриваются все варианты замены одной выбранной ноды одной невыбранной. Для управления поиском вводится сумма превышений требований:

$$
V(S)=\max\bigl(0,A(S)-\varepsilon_A\bigr)+\max\bigl(0,P_L(S)-\varepsilon_L\bigr).
$$

где:
- \(V(S)\) — штраф нарушения требований выбранного набора;
- \(S\) — размещение;
- \(A(S)\) — ожидаемая доля времени недоступности объекта;
- \(P_L(S)\) — вероятность безвозвратной потери объекта за заданное окно без промежуточного восстановления;
- \(\varepsilon_A\) — допустимая доля недоступности;
- \(\varepsilon_L\) — допустимая вероятность потери.

Меньший штраф предпочтительнее; при равенстве сравнивается графовый критерий и принятые технические признаки разрешения равенств. Это вспомогательный штраф поиска: он не превращает два вида риска в одну актуарную вероятность. Численное равенство весов превышений — экспериментальное решение Р2, не оценка денежных последствий.

Переход выполняется только при строгом улучшении полного ключа сравнения. Поэтому циклов равнозначных замен нет. По умолчанию допускается до 20 принятых замен на старт и размер. Это лимит алгоритма, а не доказательство достижения локального оптимума, если лимит исчерпан.

Все полные оценки наборов сохраняются в кэше; повторная оценка того же набора в пределах запуска не требуется. После обработки стартов выбирается лучший из всех увиденных допустимых наборов текущего размера. При отсутствии такого набора пробуется следующий размер.

## 3. Статусы и гарантии

| Статус эвристики | Значение |
|---|---|
| `feasible_found` | Найден набор, точно проходящий оба ограничения в данной конечной модели |
| `not_found` | Поиск не нашёл допустимого набора; невозможность не доказана |
| `insufficient_capacity` | Числа кандидатов со свободным местом недостаточно для нижней границы размера |

Даже если найден набор первого успешного размера, эвристика не доказывает минимальности числа чанков: меньший допустимый набор мог быть пропущен. Оптимальность в малой сети устанавливается только сравнением с полным перебором.

## 4. Воспроизводимый набор сравнения

Скрипт `prototype/compare_search.py` записывает `prototype/search_comparison.json`, включая все входные состояния, требования, размещения, счётчики и времена. Вероятности записываются точными дробями.

Использовано 20 случаев:
- пять исходных примеров Р1;
- три специально построенных случая локального минимума;
- 12 учебных сгенерированных сетей по 6–10 нод с фиксированными зёрнами от 7100.

Сгенерированные вероятности не являются калибровкой реальной сети. Три ловушки намеренно используют одну структуру с разными требованиями, а не представляют независимую случайную выборку. Набор предназначен для проверки возможностей и ограничений алгоритма, не для статистического доказательства его качества.

## 5. Результаты

| Показатель | Один старт | Три старта |
|---|---:|---:|
| Совпадение с точным оптимумом | 15 | 18 |
| Допустимый набор того же размера, но хуже по критерию | 1 | 0 |
| Лишний чанк относительно точного минимума | 1 | 0 |
| Допустимый набор пропущен | 1 | 0 |
| Точный перебор доказал отсутствие решения; эвристика ничего не нашла | 2 | 2 |
| Полных оценок наборов у эвристики | 530 | 634 |
| Полных оценок наборов у эталона | 1320 | 1320 |

Три старта в этом наборе проверили примерно на 52% меньше полных размещений, чем эталон. Однако дополнительно рассчитывались рёбра графа и кандидаты жадного расширения; число оценок не равно полному числу операций.

В первом запуске суммарное время эталона составило около 0,22–0,23 секунды на 20 случаев. Эвристика заняла около 0,12 секунды при одном старте и 0,19 секунды при трёх, включая подготовку графа. Это однократные измерения на малых сетях, параллельно с проверками; по ним нельзя заявлять устойчивое ускорение или масштабируемость. При повторном запуске времена изменяются; решения и точные риски воспроизводимы.

## 6. Контрпример локального минимума

Четыре ноды А, Б, В, Г. Вероятности совместной недоступности:

| Пара | Вес |
|---|---:|
| А–Б | 0,01 |
| А–В, А–Г, Б–В, Б–Г | 0,02 |
| В–Г | 0 |

Собственная недоступность А и Б — 0,05, В и Г — 0,07. Полное согласованное распределение задано в коде и экспортировано в отчёт; веса не назначены независимо от сценариев.

Один старт выбирает А как более доступную ноду, затем Б. Любая одиночная замена увеличивает сумму рёбер, поэтому поиск останавливается. Но В–Г — лучший набор, для перехода к которому нужно заменить обе ноды либо начать поиск с другой вершины.

Отсюда получаются три наблюдаемых исхода:
1. При мягком ограничении пара А–Б проходит, но хуже оптимума В–Г.
2. При нулевой допустимой недоступности и верхней границе в три чанка поиск с одним стартом пропускает В–Г и использует три чанка.
3. При том же требовании и верхней границе в два чанка поиск возвращает `not_found`, хотя В–Г допустимы.

В данной ловушке три старта находят В–Г. Это демонстрирует пользу нескольких стартов, но не доказывает, что трёх стартов достаточно для произвольной сети.

## 7. Проверки

Выполнены все 16 проверок через `unittest discover`: девять предыдущих и семь новых. Проверены локальный минимум, выход через несколько стартов, лишний чанк, пропуск допустимого решения, допустимость возвращаемых наборов и сравнение с эталоном, ресурсы, неверные настройки, порядок нод, одна нода и режим без локальных замен. Запуск с `-W error` прошёл без предупреждений.

## 8. Вывод и следующий шаг

Графовый поиск пригоден как кандидат для дальнейшего исследования: он уменьшил число полных оценок в учебном наборе, но может пропускать лучшие и даже допустимые размещения. Точную проверку риска объекта сохраняем после поиска; отсутствие решения остаётся статусом поиска, а не диагнозом сети.

Следующий этап Р3 — получение оценок из прошлых наблюдений, новые ноды и неполные проверки. При переходе к нему понадобится отделить ошибки модели риска от ошибок поисковика. Прогноз кризисов, очереди и интеграция основной среды пока не реализованы.
