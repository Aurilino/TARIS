# Изолированный прототип защищённого чтения

> [[56_encrypted_manifest|Архитектура]] · [[59_crypto_file_profile|Профиль]] · [[01_plan|План]]

03.11.2026 реализован локальный прототип на реальных байтах. Основной код — `crypto_demo/storage.py`; CLI — `scripts/run_crypto_demo.py`; инструкция — `crypto_demo/README.md`; отдельные зависимости — `requirements-crypto.txt`. Он не импортирует `taris_sim` и не подключён к политике размещения или потокам мира.

## Что выполнено

Объект шифруется AES-256-GCM и кодируется в избыточные фрагменты. Индексы, параметры кода, контрольные значения и ключ объекта помещаются в зашифрованный манифест. Ключ манифеста защищается отдельной оболочкой. Ключ доступа хранится на клиенте в файле, зашифрованном с использованием scrypt и AES-GCM. Агент загружает и восстанавливает фрагменты без ключей, клиент проверяет их, декодирует и расшифровывает объект.

Добавлены доверенный локальный указатель версии, сравнение ревизии до и после чтения, однописательская блокировка, резервирование ключевого файла, восстановление с новым активным ключом, перепаковка оболочек и полное повторное шифрование новой версии данных. Ротация не обещает отозвать ранее скопированные ключи или открытый текст.

## Проверки

Команда: `.venv\Scripts\python.exe scripts\check_crypto_demo.py`. Финальный прогон прошёл 20 групп проверок; машинный отчёт — `runs/crypto_demo/check_report.json`. Версии: `cryptography 50.0.2`, `reedsolo 1.7.0`; `pip check` не выявил конфликтов зависимостей.

- Для кода 3/5 перебраны все 16 наборов потерь до двух фрагментов включительно; для 10/13 — все 378 наборов до трёх потерь. Исходные байты восстановлены во всех допустимых случаях.
- В сквозном чтении три потери из 13 компенсируются, четыре дают `INSUFFICIENT_FRAGMENTS`.
- Повреждённые фрагменты исключаются; ложные ответы агента не принимаются как корректный объект.
- Неверный пароль/ключ, подмена тега, контекста, манифеста и оболочки отклоняются. Открытые данные и ключ объекта не обнаружены в файлах тестового хранилища.
- Ремонт по несекретному плану выполнен при физически отсутствующем клиентском ключевом файле.
- Проверены недоступность ключа/манифеста, конфликт ревизии, отсутствие доверенного указателя, изменение версии во время чтения и предъявление старого манифеста под актуальным доверенным идентификатором.
- Ротация сохраняет чтение текущей версии; отдельная проверка подтверждает, что прежняя копия ключа открывает прежний манифест.
- Восстановление актуальной копии ключевого файла позволяет чтение, но создаёт новый активный ключ для новых записей. Проверены сохранение nonce до шифрования и отклонение повтора.
- Проверены пустой объект, бинарные данные, дополнение RS, некорректный JSON, недопустимые параметры KDF и лимит объёма.

Проверки выполняются во временном каталоге внутри `runs/crypto_demo/`. После успешного завершения тестовые ключи и данные удаляются; отчёт не содержит секретов. Это проверка функций и границ прототипа, не доказательство стойкости криптографических примитивов и не внешний аудит.

## Малый замер накладных расходов

Один случайный объект 16384 байта, код 10/13, Windows 11 / Python 3.12. Финальный прогон: запись 2,33 с, чтение 0,85 с; фрагменты заняли 21320 байт, манифест с оболочкой — ещё 3630 байт. Ключевой файл, доверенный реестр и метаданные файловой системы в эти объёмы не включены. Операция записи включает шифрование, RS, проверку чтения и защиту ключевого файла; чтение включает KDF. Это один локальный замер, а не оценка пропускной способности TARIS.

## Ограничения и следующий шаг

Один владелец и локальные файлы. Нет сетевого протокола, реальной карты держателей, политики размещения TARIS, доказательств хранения, событий `events.jsonl` и автоматического продолжения по `request_id`. Прототип сохраняет старые ключи для чтения; он не обеспечивает криптографическое удаление старых версий. Доверенное состояние защищается границей клиента; откат самого доверенного клиентского реестра этим прототипом не обнаруживается.

Лимит nonce на активный ключ уменьшен до 1000, чтобы ключевой JSON укладывался в 256 КиБ. Исходный объект ограничен 1 МиБ; полный набор отказов проверялся на малых объектах, а не на каждом возможном размере. Крупные файлы и сетевые задержки не измерялись.

После разрешения автора продолжать без подтверждений реализован первый уровень интеграции: анализ по журналу TARIS и байтовая проверка снимков — [[61_security_integration]]. Политики и прежняя трактовка метрик не изменены; новые индексы, ротация во времени симуляции и полный adversary остаются отдельными задачами.
