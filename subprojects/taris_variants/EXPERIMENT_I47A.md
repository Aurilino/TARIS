# I4.7a — условный объём передачи

Исходные данные — только снимок `taris-queue-observation/2`. Не читать физические журналы или исполнитель. Два сценария: `trust_ack` доверяет последнему успешному префиксу на получателе; `restart_partial` повторяет незавершённый фрагмент целиком. В обоих сценариях уже полностью подтверждённые фрагменты считаются сохранившимися. Это допущение, не наблюдение текущей целостности.

Граница расчёта: текущая незавершённая передача условно прерывается без новых подтверждений, ранее подтверждённые блоки собственной памяти сохранены. Повторов, новых заявок, отмен и отказов после снимка нет; источник доступен немедленно. Каждое незавершённое repair-задание получает один успешный closing proof. Даже если все записи выполнены, отсутствие полного буфера требует восстановить его для такой проверки по текущему протоколу.

Неподтверждённая часть текущего блока передаётся заново целым блоком. Нельзя дополнительно прибавлять остаток старой фазы: он уже входит в перезапускаемую работу. Успешный prefix ACK после перезапуска с stripe=0 заменяет прежний прогресс, а не берётся максимум всех ACK.

Считаем read/write/closing-proof объёмы и условную цену только передачи, отдельно для каждого задания. Неизвестный объём самостоятельных proof-заданий отмечается явно. Не оцениваем ожидание, подготовку, занятость памяти во времени, новые потери и полный резерв. Сумма известных repair-объёмов не является полной суммой очереди при наличии proof-заданий. Деление объёма на скорость — только время непрерывной полезной передачи, не срок завершения очереди.

Проверки: ручной расчёт с частичными ACK, устаревший большой префикс после restart, завершённый фрагмент, отказ памяти, отсутствие двойного учёта текущей фазы, неизвестные proof-задания, запрет будущих ACK и некорректных параметров. Показать расчёт на фактическом runtime-снимке контролируемого примера. Новые миры не строить.
