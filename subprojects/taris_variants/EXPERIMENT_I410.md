# I4.10 — поправка по наблюдаемому состоянию

Протокол до просмотра новых миров 37–39. Миры 34–36 уже открыты, повторно чистой проверкой не считаются. Обучение только 31–33; пилот30 исключён. Цель и ограничения семисуточной передачи I4.9 сохранены.

Состояния зафиксированы функцией `observed_state` в обучающей диагностике I4.9: empty_repair_queue, parked_full_buffer, repair_transfer, proof_transfer, waiting_or_setup. Входы — только runtime-снимок. Скрытые причины ожидания и будущие исходы не используются.

Для каждого профиля канала и состояния коэффициент по прежней сетке 0–4, шаг0,01, общий для вариантов. Подгонка разрешена только если непустые строки этого состояния встречаются хотя бы в двух обучающих мирах и их суммарно не меньше пяти. Иначе коэффициент1, статус insufficient_support. Нулевые очереди дают ноль.

До окончательной модели — leave-one-world-out по 31–33: каждый мир прогнозируется по двум другим, правила поддержки те же. Сначала MSE внутри мира по всем вариантам и допустимым снимкам, затем среднее по трём мирам. Отдельный gate для профиля: если CV MSE строго меньше базиса более чем на 1e-12, разрешить state-модель; иначе весь профиль остаётся на базисе. Данные новых миров не влияют на gate, поддержку, сетку или признаки.

После фиксации коэффициентов, gate, исходных хешей и кода запускаются 37–39 прежним run_observed. Отчёт по мирам/вариантам/каналам, MAE/RMSE/смещение, непустые случаи и поддержка состояний. Если CV выигрыш не перенесётся — сохранить отрицательный результат и не подключать модель к политике. Оценка не относится к потере информации и полному актуарному резерву.
