## Названия и роли

| Идентификатор | Название | Роль |
|---|---|---|
| `classic` | **TARIS Classic** | Классический актуарный агент: оценки риска, кредибилити, резерв информации, актуарная проверка размещения |
| `graph` | **TARIS-G** (Graph) | Графовый агент: наблюдения сети, риски совместной недоступности и выбор размещения через граф |
| `hybrid` | **TARIS-Hybrid** | Классический агент определяет резерв и момент восстановления, графовый модуль предлагает улучшения размещения |

В гибриде одно итоговое решение исполняет Ledger. Два компонента не отправляют конкурирующие команды записи. Все три варианта запускаются как отдельные политики в одном и том же основном симуляторе.

## Что выполнено сейчас

Первый этап интеграции I1: начальное размещение и выбор получателей восстановления. Основные файлы `taris_sim` не меняются. Новые политики и запуск находятся здесь. Результаты пилота — `comparison_results.json`, краткий отчёт — `RESULTS.md`.

Классический вариант — непосредственно существующий `ReservePolicy`, а не переписанная копия. Зафиксирован профиль `rates="agent"`, `placement="agent_capped"`, по умолчанию `mode="thiele"`. Он использует сетевые оценки, а не истинные интенсивности оракула. Это явно выбранный эталон для данного сравнения; другие тарифные и исследовательские режимы основного TARIS не объявляются эквивалентными ему.

TARIS-G — интеграционная адаптация графового подхода этого чата. Она сохраняет смысл полного графа, совместной модели и минимизации суммы рёбер. Полное перечисление состояний прежнего прототипа заменено конечной смесью исторических состояний и базовых выборок, чтобы не ограничивать число нод десятью. Это новая приближённая модель, не доказанный перенос качества прежнего прототипа на большую сеть.

## Запуск из корня проекта

```powershell
.venv\Scripts\python.exe -B subprojects/taris_variants/run_compare.py --days 24 --seeds 1 2 --nodes 24
.venv\Scripts\python.exe -B subprojects/taris_variants/report.py
.venv\Scripts\python.exe -B -W error subprojects/taris_variants/run_series.py
.venv\Scripts\python.exe -B -W error subprojects/taris_variants/run_adaptive.py
.venv\Scripts\python.exe -B -W error subprojects/taris_variants/audit_sizing.py
.venv\Scripts\python.exe -B -W error -m unittest discover -s subprojects/taris_variants -p "test_*.py" -v
```

По умолчанию сравниваются S0/S2. Для первой проверки S6/S8 не включены: это не серия кризисных испытаний. Изменение сценариев и кризисов — следующий этап, а не молчаливое сокращение допустимого горизонта S6.

Основные параметры запуска: `--days`, `--seeds`, `--scenarios S0 S2`, `--nodes`, `--k`, `--fragments`, `--block-days`, `--reserve-horizon`, `--repair-mode thiele|fixed`, `--output`.

Начальные значения пилота: четыре чанка, нужны два; одинаковый бюджет для всех вариантов. Для другого кода можно задать, например, `--k 10 --fragments 13`; это не обещание, что столько чанков будет допустимо при любом числе операторов и ёмкости.

Режим `fixed` задаёт Classic и Hybrid фиксированный порог немедленного восстановления признанных потерь. Это полезная абляция влияния актуарного выбора момента. TARIS-G восстанавливает признанные потери сразу и не использует Тиле. В режиме `thiele` сравниваются полные заданные стратегии, а не только различие размещения.

## Наблюдения и граф

`ObservedRiskGraph` получает только прошлый `view.step`, время регистрации и зарегистрированные ноды. Завершённые интервалы и текущие простои преобразуются в почасовые наблюдаемые состояния. Повторно переданный отрезок не считается новым опытом. Будущий отрезок отвергается.

Хранится окно до 30 суток. Базовая смесь имеет вес 48 часовых наблюдений и 128 случайных состояний: индивидуальная недоступность 0,02 и общий шок заявленной площадки 0,01. Добавлены состояния одиночного отказа для положительного риска новых нод. Эти числа — экспериментальные допущения, не калибровка основного мира.

Для отсутствовавших в истории нод неизвестные значения дополняются базовым состоянием. Это простое однократное дополнение, а не EM из прежнего малого прототипа. Вариация такого дополнения и консервативные ансамбли в I1 ещё не включены. Риски считаются по всем состояниям смеси: и рёбра, и доступность объекта берутся из одного распределения.

Потоки базовых выборок привязаны к идентификаторам уже известных нод и площадок. Метаданные и число будущих нод не меняют оценки уже известных. Генераторы политики не используют потоки мира.

## Выбор размещения

Сначала строится исходный набор с публичными ограничениями концентрации по площадке, провайдеру, региону, кошельку и подсети. Затем выполняются до двух локальных замен с кандидатами из 16 низкорисковых нод. Ни один тип концентрации не может стать выше максимума исходного набора. При восстановлении существующие держатели не перемещаются.

Принимается только строгое уменьшение суммы рёбер. Нельзя превратить проходящий целевой уровень доступности набор в непроходящий; если исходный набор уже не проходит, локальная замена не должна ухудшать его оценку доступности. Отсутствие допустимого улучшения сохраняет исходный набор. Это ограниченный поиск, а не доказательство глобального минимума.

В Hybrid после обучения классической модели замена дополнительно не должна увеличивать актуарную оценку потери набора относительно исходного предложения. При первичном размещении также действует существующая проверка `agent_capped`. До первой успешной подгонки актуарная проверка недоступна и это отмечается в журнале. Невыполнимый cap может приводить к явно учитываемому нарушению по прежнему правилу Classic; абсолютной гарантии Hybrid не заявляет.

`graph_decisions` — журнал предложений локальной доработки, включая варианты, которые родительская политика затем могла не выбрать. `placement_decisions` — итоговый ответ политики размещения, `repair_requests` — запросы ремонта, а `initial_placements` и счётчики `repairs` извлекаются из фактически исполненного Ledger. Предложение не считается исполненной операцией.

## Ограничения сравнения

- Число чанков в I1 фиксировано: собственная минимизация их числа из малого прототипа пока не перенесена. Сначала измеряется вклад выбора мест при одинаковом бюджете.
- Граф оценивает доступность, а не физическую потерю. Hybrid использует дополнительную актуарную модель основного TARIS.
- Смысл потери остаётся прежним в Ledger: длительное молчание может административно исключить чанк из существующих. Метрики пилота нельзя объявлять только физическими повреждениями.
- Буфер, очереди, перегрузка, предупреждения и механизм восстановления из автономного прототипа не подменяют основной Ledger в I1. Новая политика использует его прежнее исполнение.
- Сравнение не доказывает качество обучения на больших сетях или длительном кризисе. Расчёт матрицы всех пар имеет квадратичную память.
- Численные RuntimeWarning существующих моделей перехватываются только для записи в отчёт, без изменения чисел. Конечность весов и коэффициентов проверяется; нефинитная модель прерывает запуск. Наличие конечных коэффициентов само по себе не доказывает статистическую устойчивость GLM.
