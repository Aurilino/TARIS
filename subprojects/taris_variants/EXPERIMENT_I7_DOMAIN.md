# I7 — минимальный запас при совместном отказе доменов

Первый шаг — математический критерий и чистый решатель без изменения агента, основной модели или старых серий. I6.2закрыт; его миры201–203уже открыты и не могут служить чистой проверкой новой политики.

Класс задачи: код с порогомk, один физический экземпляр каждого номера в новом плане, не больше одного номера объекта на узел. Узлы сгруппированы по достоверным наблюдаемым ДЦ. Входы — число доступных различных узлов каждого домена, k, фиксированный бюджет bодновременных отказов и верхний предел числа фрагментов. Не читать будущие отказы и настоящую скрытую целостность.

Цель: минимальное общее число номеров, для которого после отказа любых bдоменных групп остаётся не меньшеkразных номеров. При ограничениях числа узлов задача может быть неразрешима; явно возвращать infeasible, а не сертифицировать best_effort. Пока это не политика приёма данных: пустой план нельзя автоматически выдавать за сохранение информации.

Сначала вывести точный минимум без ограничений ёмкости внутри доменов, затем реализовать ограниченный целочисленный поиск по числу номеров в каждом домене. Подтвердить минимум независимым перебором малых раскладок. Примеры: k2,b2и4доступныхДЦтребуют4номера; k2,b3и5ДЦ—5номеров; при4ДЦпосле3отказов каждый оставшийся ДЦдолжен содержать2номера, всего8. Упрощение «всегдаk+b» неверно при малом числе доменов.

Проверки: различные номера, минимальность, ограниченные доменные ёмкости, недостаток доменов/узлов, бюджет меньше необходимого, перестановка меток, отсутствие влияния будущей жизни узлов, честный статус при ограничении перебора. Дубликаты существующих копий учитываются в физическом аудите отдельно и не подменяют число разных номеров.

Бюджетыb2иb3—внешние фиксированные классы защиты, не извлекаются из будущего расписания close/far. b3покрывает накопление трёх доменных отказов до восстановления, но не обещает покрыть любой реальный кризис. Достоверность доменных меток, скрытые потери, старение и успешность первичной записи — отдельные условия сертификата; dc=-1частных устройств не считать автоматически независимыми ДЦ.

После решения и тестов — отдельная политика, учитывающая уже известные размещения и pending-цели без двойного бронирования ДЦ. Нельзя молча ослаблять прежние ограничения владельцев/провайдеров или добавлять истину в выбор. Сначала диагностический пример, затем заранее выделенные новые миры и одновременный отчёт сохранности, числа чанков, отказов приёма и затрат. Реальные вероятности доменных катастроф и полный резерв остаются неоценёнными.
