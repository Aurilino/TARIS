# TARIS — симулятор хранения данных блокчейна

Код шага 3 (среда). Спецификация — [docs/30_step3_simulation_spec.md](docs/30_step3_simulation_spec.md); все документы работы — в папке `docs/`; папка проекта открывается в Obsidian как хранилище.

## Просмотрщик

```powershell
python scripts\export_run.py runs main                     # журнал основного мира (оракул кризисов, около 5 минут)
python scripts\check_export.py                              # проверки журнала
python scripts\check_graph.py                               # проверки графа связей
python scripts\build_viewer.py runs\main_crisis_oracle13_matched.taris.json.gz
start viewer\build\taris_viewer.html                        # страница со встроенным журналом; «Открыть журнал» — любой другой
```

Страница грузит Cytoscape.js и шрифты из интернета; журнал распаковывается в браузере. `viewer\build\taris_viewer_artifact.html` — та же страница для публикации.

## Запуск (Windows 11, PowerShell)

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python scripts\check_world.py          # проверки мира
python scripts\check_chain.py          # проверки наблюдения
python scripts\plot_world.py figures   # графики A–D
python scripts\plot_chain.py figures   # графики E–F
python scripts\check_ledger.py         # проверки учёта (около минуты)
python scripts\check_crisis.py 10      # проверки кризисов в сценарии S6 по 10 зёрнам (около 25 минут)
foreach ($p in "uniform15","uniform13","oracle13") { python scripts\run_baselines.py runs $p }   # 1–3 минуты каждая
foreach ($p in "oracle13","crisis_oracle13") { python scripts\run_baselines.py runs $p S6 matched }   # S6: 5 и около 16 минут
python scripts\plot_ledger.py runs figures   # графики G–H
python scripts\plot_crisis.py figures        # график I: профиль предвестника глазами сети (около 5 минут)
```

## Устройство

- Единица времени — сутки (эпоха). Длительности простоев задаются в часах.
- Возраст в согласованном мире входит как `1 + age / 30` (в месяцах плюс один), чтобы избежать логарифма нуля.
- `beta_0` калибруется так, что средняя по сети частота страховых случаев равна `mean_event_rate` в обоих режимах мира.
- Простой, начавшийся во время другого простоя того же узла, сливается с ним.
- Микропрерывания генерируются в `chain` из потока `rng.MICRO` по каждому узлу (не зависят от политики).
- Пинги идут по сетке с шагом 5 минут и своей фазой у каждого узла; наблюдаемый простой — серия проваленных пингов.
- Добавлен параметр `ping_noise` — ложный провал пинга из-за шума сети (в спецификации шум был задан только для аудитов).
- Наблюдения зависят только от мира, поэтому строятся заранее; `step()` выдаёт их по эпохам.
- Целостность фрагмента при аудите проверяет `ledger`: только там известно, какие фрагменты лежат на узле.
- Политика принимает решения на границах эпох: восстановление запускается в начале эпохи и длится `repair_hours`.
- Аудит проверяет все фрагменты узла (как ежедневное доказательство хранения); тихая потеря обнаруживается на первом аудите при доступном узле.
- Простой дольше `T_rep` для сети равен утрате фрагментов узла, даже если данные на нём целы.
