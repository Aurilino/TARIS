# Локальный прототип зашифрованного манифеста

Работает с настоящими байтами и готовыми AES-GCM / Reed–Solomon. Не подключён к `taris_sim` и не меняет случайные потоки мира. Используйте тестовые данные: доверенный каталог клиента и память процесса входят в границу защиты.

## Быстрая проверка

Из корня проекта в PowerShell:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-crypto.txt
.venv\Scripts\python.exe scripts\check_crypto_demo.py
```

Проверки создают временный каталог внутри `runs/crypto_demo/`, удаляют тестовые ключи и сохраняют только несекретный `check_report.json`. Отдельно перебираются 16 допустимых наборов потерь для кода 3/5 и 378 для 10/13. Проверяются сквозное чтение, подмена, потеря, ключи, ремонт, версия и ротация. Это функциональные проверки прототипа, не независимый аудит безопасности.

## Ручная демонстрация

```powershell
.venv\Scripts\python.exe scripts\run_crypto_demo.py init
.venv\Scripts\python.exe scripts\run_crypto_demo.py store docs\02_student.md
.venv\Scripts\python.exe scripts\run_crypto_demo.py read <object_id> runs\crypto_demo\restored.md
.venv\Scripts\python.exe scripts\run_crypto_demo.py repair <object_id>
.venv\Scripts\python.exe scripts\run_crypto_demo.py rotate
.venv\Scripts\python.exe scripts\run_crypto_demo.py reencrypt <object_id>
.venv\Scripts\python.exe scripts\run_crypto_demo.py backup runs\crypto_demo\key-backup.json
```

`<object_id>` заменяется значением из ответа `store`; это не буквальный аргумент PowerShell. Пароль запрашивается скрыто при каждом запуске. Корень по умолчанию — `runs/crypto_demo/manual`; другой задаётся параметром `--root` до команды. Чтение пишет результат только в новый файл вне корня прототипа. `rotate` меняет ключ доступа и оболочки; `reencrypt` заново шифрует содержимое с новыми ключами.

Для восстановления при утраченном `keystore.json` выполните `restore <путь-к-копии>`. Существующий ключевой файл эта команда не заменяет. Требуются прежний пароль и актуальная резервная копия; старые копии не открывают ключи, появившиеся после их создания. Доверенный `head-store.json` резервируется отдельно, и актуальность восстановленной записи должна быть известна владельцу. Новое устройство не получает защиту от отката из одной старой копии.

## Реализованные границы

- Клиент шифрует объект, агент хранит и получает фрагменты; клиент декодирует и проверяет подлинность.
- Манифест содержит секретный ключ объекта, но хранится только зашифрованным. Оболочка защищает ключ манифеста ключом доступа.
- Ремонт работает с несекретным планом, без клиентских ключей.
- Все фрагменты проверяются по аутентифицированному описанию; AEAD проверяется после сборки. Некорректные данные не выдаются как успешный результат.
- Ключевой файл защищён scrypt и AES-GCM. Он не заменяет аппаратное/системное хранилище. Ключи доступны доверенному Python-процессу в памяти.
- Локальный доверенный реестр проверяется в начале и конце чтения. Атомарная замена и блокировка ограничивают запись одним процессом; после аварии может остаться `.writer.lock`, который требуется проверить перед ручным снятием.
- История nonce сохраняется до шифрования оболочки. После восстановления копии создаётся новый активный ключ. Ранее использованные ключи сохраняются только для чтения, а не для нового шифрования.

## Ограничения демонстрации

Один владелец, один локальный держатель каждого фрагмента, без сетевого транспорта, фактической политики разнесения, `Locator`, `events.jsonl` и ончейн-реестра. CLI проверяет доступность прямым чтением, а не доказательством хранения. Ограничения размещения TARIS и сценарии Сибиллы сюда ещё не встроены. Запись `request_id` и автоматическое возобновление операций не реализованы; это следующий уровень интеграции.

Лимит исходного объекта — 1 МиБ. Локальный реестр и keyfile ограничены 256 КиБ; реестр nonce допускает 1000 оболочек на активный ключ (уменьшено относительно первоначального проекта, чтобы уложиться в размер JSON). При исчерпании требуется ротация. Повторное шифрование больших объектов через чистый Python RS может быть медленным; потоковое кодирование и крупные объекты не реализованы.

Компрометация клиентского каталога/процесса, сетевые шаблоны доступа и аудит библиотек остаются за границами демонстрации. Скопированные старые ключи и открытые данные отозвать нельзя; тест явно проверяет эту границу. Старые ключи в локальном vault автоматически не удаляются, а ротация всех объектов не является одной общей транзакцией: после сбоя часть оболочек может остаться старой, при этом ключи для чтения сохраняются.

## Снимки настоящего прогона TARIS

`replay.py` связывает доступные индексы из RunResult с реальными зашифрованными байтами. Запуск: `python scripts/run_security_demo.py`; проверки: `python scripts/check_security.py`. Это анализ после прогона, не новая политика и не полный adversary. Спецификация и результаты — `docs/61_security_integration.md`.
